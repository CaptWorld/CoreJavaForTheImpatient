## Part A: generator instructions

- Maven project with `mvnw`, Java 24, JUnit 5. Exercise sources in
  `src/main/java/chNN/exNN`, tests in `src/test/java/chNN/exNN`.
  Packages have names like `ch01.ex01`; exercise classes are `ExNN`.
- Each exercise is one public class with public static methods. Stub bodies
  are `throw new UnsupportedOperationException("TODO");`.
- Class-level Javadoc in `<pre>` carries the complete Part B statement and
  expected time. Each file ends with a `MY NOTES` block beginning
  `Actual time: ___ min`, followed by every supplied question and blank answer.
- Reference gate: write correct implementations with the same packages and
  class names in `src/ref/java`. `./mvnw -Pref test` must pass every test;
  default learner sources contain only stubs. Fix and report any test that
  cannot pass on a correct solution; never loosen a test silently.
- Every test must fail on the stub and pass on a correct solution. Put
  `@Timeout` on every test. Tag stretch exercises `@Tag("stretch")`.
- Do not add solutions, hints, or extra edge cases beyond the statements to
  learner files. Do not name pitfalls in display names or assertion messages;
  messages describe expected versus actual results for the scenario.
- Use realistic scenarios with exact expected output, invariants/round trips,
  and fixed-seed randomized comparisons against simple references in tests.
  Pass `RandomGenerator`, `Locale`, and streams explicitly; I/O `main` methods
  are thin wrappers around `run`.
- Self-policed constraints are not tested.
- Explorations are `ch01.explore.Explore01` through `Explore04`, with task
  Javadoc, a `main` containing only `// TODO`, and blank notes. No tests.
  Shell commands and experimental results go in the notes.
- Each chapter starts fresh, without depending on earlier solutions.

Build choices: Java release 24; JUnit 5.11.4; Surefire 3.5.2;
Compiler Plugin 3.16.0; Maven 3.9.9; Wrapper Plugin 3.3.2. The `ref`
profile overrides `main.src`. Separate `target/learner` and `target/ref`
directories prevent stale references from being used by learner tests.
Normal timeouts are 10 seconds; statistical tests and the million-start
Collatz test receive 30 seconds. Refer to the README for commands.

### Ex01: Unsigned calculator (warm-up, about 20 minutes)

```text
Two small utilities about the 32 bits inside an int.

1) public static String radixReport(int n)      // n != 0
   Returns one line: "<n>: bin=<b> oct=<o> hex=<h> recip=<r>"
   b, o, h are the binary, octal and hexadecimal digits of the 32-bit
   two's complement pattern of n (no prefixes, no leading zeros, lowercase hex).
   r is 1.0 / n as a double written as a hexadecimal floating-point literal.
   Examples:
     radixReport(10) -> "10: bin=1010 oct=12 hex=a recip=0x1.999999999999ap-4"
     radixReport(-8) -> "-8: bin=11111111111111111111111111111000 oct=37777777770 hex=fffffff8 recip=-0x1.0p-3"

2) public static String[] unsignedArithmetic(String a, String b)
   a and b are decimal strings of integers in 0..4294967295 (b is not "0").
   Treat both as unsigned 32-bit values, keep them in int variables
   (self-policed: do not widen to long or BigInteger), and return
   { sum, difference, product, quotient, remainder } as decimal strings
   of the unsigned 32-bit results (sum, difference and product are modulo 2^32;
   the quotient is the integer quotient).
   Example: ("4294967295","2") -> { "1", "4294967293", "4294967294", "2147483647", "1" }

Tests: radixReport for 10, -8, 3 and 255; unsignedArithmetic for four
scenarios; and a randomized comparison (fixed seed, 500 pairs including values
above 2^31) against a BigInteger-based reference inside the test.

Exact values [verified]:
radixReport(3) -> "3: bin=11 oct=3 hex=3 recip=0x1.5555555555555p-2"
radixReport(255) -> "255: bin=11111111 oct=377 hex=ff recip=0x1.010101010101p-8"
unsignedArithmetic("3000000000","1500000000") -> {"205032704","1500000000","1900150784","2","0"}
unsignedArithmetic("5","7") -> {"12","4294967294","35","0","5"}
unsignedArithmetic("10","3") -> {"13","7","30","3","1"}
```

### Ex04: Unicode text tools (about 30 minutes)

```text
All lengths below count Unicode code points (a character outside the
basic plane, such as an emoji, counts as one).

public static String[] describeNonAscii(String line)
   One entry per non-ASCII character, in order, formatted "U+%04X <char>".
   "naïve café 😀 ok" -> { "U+00EF ï", "U+00E9 é", "U+1F600 😀" }

public static String truncate(String s, int max)    // max >= 1
   If s has at most max code points it is returned unchanged. Otherwise the
   result is the first max-1 code points followed by the single character "…" (U+2026),
   so the result has exactly max code points.

public static String centered(String s, int width)
   Pads s with spaces to the width. The left padding is (width - length) / 2
   rounded down and the rest goes on the right. If s is not shorter than width,
   it is returned unchanged.

Tests: the scenarios below; randomized strings (fixed seed, built from a pool that
mixes ASCII, accented letters and emoji) checking that truncate returns a string with
no more than max code points, that it is a code-point prefix of the input plus "…",
that no unpaired surrogate appears in any result, and that centered
always has max(width, length) code points.

Scenarios [verified], t = "héllo wörld 😀😀" (14 code points, 16 chars):
truncate(t, 14) -> t; truncate(t, 13) -> "héllo wörld …";
truncate(t, 12) -> "héllo wörld…".
truncate("ab😀cd😀ef", 5) -> "ab😀c…"; truncate("short", 10) -> "short".
centered("hi", 7) -> "  hi   "; centered("😀", 4) -> " 😀  ";
centered("héllo", 4) -> "héllo".
```

### Ex05: Random draws (about 40 minutes)

```text
All randomness comes from the RandomGenerator parameter (self-policed: do not use
Math.random or create your own generator).

public static int roll(String expr, RandomGenerator rng)
   expr has the form "NdM", "dM", "NdM+K" or "NdM-K": N dice (default 1, at most 100),
   each with faces 1..M (M >= 2), plus or minus the modifier K.
   "3d6+2" is the sum of three d6 plus 2; "d20" is one d20; "2d8-1" is two d8 minus 1.

public static int[] draw(int count, int max, RandomGenerator rng)
   Lottery draw: count distinct numbers from 1..max (1 <= count <= max),
   returned in ascending order.
   Self-policed: start from an ArrayList<Integer> holding 1..max, repeatedly pick a
   random position and remove that element, as the book's exercise says.

public static String randomId(int length, RandomGenerator rng)
   A string of exactly `length` characters (length 1..40), each one of 0-9 or a-z, with every
   character equally likely at every position.
   Self-policed: build it by printing random long values in base 36.

Tests (fixed seed new Random(12345)):
  roll("d6") 6000 times: every face from 1 to 6 appears between 800 and 1200 times;
  roll("3d6+2") 20000 times: all values in 5..20 and the mean is within 0.2 of 12.5;
  roll("2d8-1") stays inside 1..15; roll("d20") stays inside 1..20.
  draw(6, 49): 20000 draws, each draw has 6 distinct ascending values in 1..49,
  and each number appears between 2150 and 2750 times in total.
  draw(5, 5) is {1,2,3,4,5}; draw(1, 3) always returns one value in 1..3.
  randomId: lengths 1, 8, 13 and 40 give exactly that many characters from the allowed set;
  for 36000 ids of length 8, each of the 36 characters appears between 700 and 1300 times at
  each of the 8 positions.
```
